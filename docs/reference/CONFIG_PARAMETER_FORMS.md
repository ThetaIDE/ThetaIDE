# Configuration parameter forms

These interaction rules apply to experiment, group-default, component, plugin, and optional configuration boxes. Preserve box-specific layouts and specialized editors: Methods keeps its method cards, Figures and Tables keeps its two-column figure cards, and Recorded Metrics keeps its section/metric toggle picker. Standardize their shared controls, not their entire presentation.

- Use the shared `ToggleSlider` for boolean controls, including metric selectors; never introduce checkboxes.
- Keep the experiment box's runtime boolean controls in a compact horizontal `FlowLayout` that wraps complete label/toggle/action groups with the available width. Their containers have transparent backgrounds, matching the card beneath them.
- Numeric parameter inputs throughout Theta use the shared `SpinBox`, `DoubleSpinBox`, or `integer_field` controls without up/down arrow buttons. Keep typed editing and numeric validation. The seed parameter has no Random action.
- Keep card styling on `ConfigBox`; identify sections with `configSection`, preserving the shared `configBox` theme property.
- Put the top-level parameter **+ immediately beside the box title**, before any stretch or trailing actions. It adds only top-level parameters.
- Put a **+ beside a parameter with children**. It adds children to that parameter, not unrelated top-level fields. Scalar selectors such as Sampler and Component can also own child parameters.
- Give every optional configured parameter an **× that appears on row hover**. The hover area is its own label/field row within its column, never the same horizontal band across the entire card. Reserve the action's space while hidden so fields do not shift. Required fields never get removal controls. Use component JSON Schema `required` declarations where available; specialized editors declare their required controls explicitly.
- Render children in `IndentedHierarchyBlock`, with the same indentation increment at every depth. Insert groups as spanning form rows, never inside the parent's value column. Keep the parent header/selector outside its child block.
- In experiments and group defaults, let the Description editor fill its row. Use the shared `ExpandingTextEdit` to wrap text and grow or shrink with its contents and available width, preserving typed line breaks. Below it, use the shared two-column layout with aligned physical rows for Paradigm, Environment, and Site. Keep Environment and its indented overrides (such as `num_envs`) together in the second column, and let Site fill the row under Paradigm beside those overrides, above the separator for trainer and run settings.
- Always show Site in experiment and group-default boxes above the runtime separator. An absent selector inherits Local or the group site without creating an override. Resource overrides use its child controls and the shared nested form.
- Integer editors must preserve the configured value exactly, including storage byte limits above Qt's 32-bit spin-box range. Use the shared `integer_field` factory for integer controls; it selects `IntegerField` for large values or schema bounds. Do not clamp a loaded value to a UI-only limit or convert it through floating point. Invalid edits must not change the stored YAML.
- Align labels and editors consistently within each layout density. Ordinary forms share label/editor widths; two-column figure cards use the shared compact widths. Boolean toggles and rich editors retain their intrinsic shape. Use `_parameter_row(..., expand=True)` for fields such as Description that should fill the available row width.
- Editors inside two-column layouts may shrink to the shared numeric field width to leave room for indentation, labels, and row actions. This includes selectors such as Site with both add and remove actions; keep them beside their labels at the normal card width. Shared forms wrap long rows when necessary. Parameter labels stay on one line and clip at their label column. Hovering the label reveals its text above the editor without changing geometry; moving onto the editor hides the reveal. Editors otherwise remain clear of their labels.
- Parameter labels support dragging after the platform's normal drag threshold, with no persistent handle or cursor affordance. Show a themed preview at the row's current width and scale, fading to the right; tall groups also fade downward. Reflow existing editors live, keeping child blocks with their parent. Reorder only within the originating sibling list in the same box and nesting level. Editors, toggles, disclosure buttons, and action buttons retain their own gestures. Escape or releasing outside that list cancels the move.
- Save parameter display order per file and sibling list in `config_viewer.parameter_orders`, retaining positions for temporarily absent optional fields. Display ordering must not change YAML values, create inherited overrides, or mark the configuration dirty.
- Structural updates must refresh dependent controls immediately, retain the viewport, and guard against reentrant rendering. Use a local box refresh when dependencies affect only that box; ordinary scalar edits and dragging must preserve existing editors.
- Keep inherited defaults distinct from explicit overrides. Adding an override preserves its selector's component identity. Removing an optional override must not silently change another parameter.
- Swept parameters show the sweep-type selector as a compact subtitle below the parameter label. Put range bounds inline as `(lower, upper)`, with optional step controls alongside them. Sweep numeric bounds, steps, and list entries grow from their compact minimum to fit the text being typed, including intermediate decimal zeros; measure the actual editor font and avoid duplicate padding on numeric controls. Lists use comma-separated, content-sized editors (retaining dropdown choices where available), a trailing **+**, and the shared `FlowLayout` to wrap complete entries. Configure-sweep buttons and sweep-list entry removal buttons float outside their entry/row on hover, without occupying layout space in either state. They remain on the same line and clickable beyond the entry bounds. Once revealed, their hover area extends continuously from the owning row across the gap to the floating button, and ends when the pointer leaves that combined area; revealing them must not resize entries, wrap a flow line, or activate a layout synchronously. Ordinary parameter removal buttons retain fixed slots; their reserved width does not change on hover. Center add buttons with the editors on their flow line, use a transparent, borderless sweep-type subtitle, and keep added steps/list entries in the owning sweep row as it wraps. Preserve the underlying unswept value. Use shared numeric controls for bounds, including scientific notation and exact large integers; invalid edits must not change YAML.
- Sweep mode follows the presence of `tuning` in the composed experiment, including group defaults imported through Hydra. Do not render a separate `sweep` or `tuning.enabled` control. Legacy flags do not affect activation. An explicit `tuning: null` masks inherited tuning; removing the sweep component creates that mask when needed. Box visibility and objective-only scoring do not determine sweep mode.
- Ruleset controls show the complete runtime resource catalog in nested directory/environment menus, independent of the experiment's environment or `symbolic_name`. New selections store qualified `environment/ruleset` values; compatibility is the experiment author's responsibility. Preserve existing bare names until edited, resolving those with the effective environment as training does. The open action opens the selected ruleset folder, including selections from another environment; an unscoped bare name opens the rules catalog instead of offering every matching basename. Use the shared `HierarchicalComboBox` for these menus, including parameter-add dialogs.

Shared implementation lives in `frontend/config_panel/` (the former import locations in `config_viewer.py` remain compatibility re-exports):

- `controls.py`: `ConfigBox.set_header` / `_parameter_header` own titles; `ParameterRow`, `ParameterForm` and `IndentedHierarchyBlock` own geometry at construction. There is no post-render standardization pass. Long labels clip to one line and reveal over the field on label hover only. Ordinary forms use 180/220 px label/editor widths; compact regions use 120/140 px; method forms declare their specialized editor width.
- `rendering.py`: `ParameterNode` / `render_nodes` own ordinary recursive presentation. Declare parent/child membership through nodes or `ParameterForm.add_parameter` / `add_children`, independently of adjacent Qt items. Model and shared-method adapters use the same renderer.
- `editors.py`, `document.py`, `bindings.py` and `domain.py`: typed editor commits, validation, explicit/inherited values and domain capabilities. Parse YAML only in explicit raw-value dialogs. Invalid number/list drafts leave storage unchanged; text such as `"false"` remains text.
- `layout.py`: responsive regions and explicit physical row slots. Context dragging retains cross-column movement through mutable slots in logical order; resizing preserves that order. Collapse to one column when the measured row minimums cannot fit. Each nested child row consumes an alignment slot.
- `sections/`: section composition and explicit rich-editor/domain hooks. Specialized compositions reuse shared controls for ordinary parameters.

`frontend/parameter_reorder.py` owns logical sibling groups, live form/region/flow reordering, drag previews, cancellation, and edge scrolling. Regions declare their logical groups before placement. `_setup_parameter_reordering` persists stable path/region scopes and migrates identifiable legacy keys without overwriting old preferences. The sweep editor uses `_refresh_sweep_box` for declared `when` dependencies, including non-selector dependencies. Shared expanding text editors notify their owning layouts of content-height changes, preserving sibling placement on native Qt as text grows.

See the [implementation and extension guide](../development/CONFIG_PANEL_IMPLEMENTATION_STATUS.md) for the section/path inventory, normalization decisions, extension recipe and verification limits.

When adding or changing a box, update the cross-box tests in `tests/test_parameter_forms.py`. Test placement, nested geometry, required/optional removal, hover stability, and actual add/edit/delete behavior. Do not create a separate implementation or style for a new box.

Tuner control availability follows [extension contributions/readiness v1](EXTENSION_CONTRIBUTIONS.md).
Offer a new tuning block only when an enabled compatible provider contributes setup;
offer parameter sweep editors only for the selected ready provider. Keep unavailable
saved search spaces as read-only values with an actionable provider diagnostic.
Availability never deletes or deactivates the saved `tuning` block. New blocks record
an explicit provider and its required defaults in namespaced options. Providers own
`legacy_flat` reads and `required_when` field requirements; generic host controls must
not branch on a particular tuner ID. Readiness-changing edits refresh dependent
controls, and floating actions are detached when their owning rows are destroyed.
For a saved mapping with a missing, blank or malformed `tuning.component`, retain
the mapping and show **Select a tuner** with a diagnostic. Never fill the selector
merely because one provider is available. Preserve saved options and range values;
keep ranges read-only until an explicit valid selection enables them. Selecting a
provider refreshes method range controls as well as the tuner settings box.
