# Layer ownership and compatibility contract

This is the active ownership contract for the [implementation plan](../plans/LAYER_BOUNDARY_IMPLEMENTATION_PLAN.md). Storage cutovers and optional-component extraction must pass their acceptance gates before old paths are retired. Current on-disk compatibility remains described in [Plugin storage](PLUGIN_STORAGE.md).

| Layer | Responsibility | Dependencies |
| --- | --- | --- |
| Core (currently `src/app` and `frontend`, eventually `src/ide`) | Configuration, discovery, orchestration, desktop, transport, shared contracts | Core and declared third-party libraries; selected extensions through public contracts |
| Packages (`src/plugins`) | Implementations, immutable defaults, assets, declared dependencies | Public core APIs, package-relative code, declared public package exports |
| User (`src/usr`) | Authored packages, editable config overrides, dataset bytes | Public core APIs and explicitly selected compatible providers |

Core must not branch on extension IDs, backend names or institution names. Lightning and the four base paradigms are retained core implementations. Slurm and tuning are optional components; installing them must use the same APIs as any independent implementation. Contributions require generic compatibility, enabled-state and readiness checks. Saved references to absent providers require actionable errors.

## Configuration authority

Package defaults stay inside their package. Editing a default explicitly creates a complete user override; updates and uninstall must not overwrite that override. `python run_pipeline.py component --root WORKSPACE config override model/package/profile` creates a recoverable copy under `src/usr/config`, retaining comments and Hydra headers. Repeating it preserves existing edits. Resolution precedence is a `src/usr/config` override, a legacy workspace profile in `in/config`, a selected provider profile, then framework fallback. Draft previews temporarily precede these sources. Conflicting package profile owners are errors; capability ownership overrides must also select the corresponding profile and schema. Package IDs, Hydra selectors and serialized class identity remain stable across storage changes. Arbitrary partial YAML merging is not supported.

New scaffolds create editable profiles under `src/usr/config`, with declared provider defaults under the authored package's `configs/`. Export reads effective profiles and retains storage-v2 archive destinations. ARC/NCShare site templates are owned by the optional Slurm component; explicit connection edits to managed templates create usr overrides that survive its update or uninstall. A non-local site profile must declare `site.scheduler` ([scheduler contract](SCHEDULER_CONTRACT.md)).

Workspace context is passed explicitly through reusable services. Entry points (the desktop host, validation worker, `run_pipeline.py`, CLIs) may select a process workspace; `configure_workspace` only records that selection in the process environment and never rebinds module constants. Omitted service context resolves through `WorkspacePaths.for_process()`, never a raw CWD guess. App plugins read the host's selection through `PluginContext.workspace_paths()`. The application root supplies code/assets/defaults; the selected workspace supplies research inputs/configuration/state. Neither is inferred from the other's existence. GUI metadata, method/schema selection, composition and worker Hydra discovery use `ConfigResolver`; the small `hydra_plugins/theta_config_source.py` adapter preserves ordinary Hydra defaults semantics. User dataset bytes have target home `src/usr/datasets`; deliberate external references remain external. Until the journaled migration and all consumers pass their gates, `in/` remains the supported compatibility layout, with no automatic data moves. Existing editor actions that explicitly target legacy files retain their current behavior during this transition.

## Public integration surface and exceptions

Packages import host code only from the versioned [Theta SDK](SDK.md) (`src.app.api`, SDK 1.0); its exports are the canonical objects behind the contracts below. The existing public contracts are [API](API.md), [execution v1](EXECUTION_CONTRACT.md), [data loaders](DATA_LOADER_CONTRACT.md), [monitors](MONITOR_CONTRACT.md), provider capabilities, [extension contributions/readiness v1](EXTENSION_CONTRIBUTIONS.md), [schedulers v1](SCHEDULER_CONTRACT.md), the local tuner protocol, [portable tuner execution v1](TUNER_EXECUTION_CONTRACT.md) and declared package exports (`provider_export`, see [plugin storage](PLUGIN_STORAGE.md#cross-package-exports)). New APIs must be general and tested with independent providers; this list does not make arbitrary `src.app` or `frontend` modules public. `tests/test_sdk_boundary.py` enforces this for the optional components, bundled component packages and bundled app plugins. At consolidation `src.app.api` becomes `src.ide.api`, with forwarding.

| Exception | Reason | Support/retirement policy |
| --- | --- | --- |
| Lightning execution and four base paradigms | Confirmed product scope | Supported core implementation; extraction deferred |
| Fixed aliases in `src/app/core/import_aliases.py` and `src/usr` shims | Saved Python targets and checkpoints | No new provider aliases; retire only at a declared checkpoint compatibility boundary with fresh-process tests |
| `hydra_plugins` discovery namespace | Hydra requires third-party discovery outside core namespace | Long-term small forwarding adapter; implementation belongs to the provider |
| API-1 plotter no-argument constructors | `create_plotter` scopes the host workspace through BasePlotter with a ContextVar, without CWD/environment mutation | Bounded compatibility adapter; new constructors accept `paths`; retire with provider API 2 |
| Historical top-level site selector YAMLs | Forward existing ARC/NCShare selectors (`ncshare_common`, …) to the Slurm component's nested profiles; core derives aliases from the forwarding files, not a name table | Owned and shipped by the optional Slurm component; retire with a declared saved-selector boundary |
| API-1 Slurm import adapters (`src/app/sites/slurm.py`, `src/app/pipeline/slurm.py`, `src/app/sites/resources.py`, `execution.worker_threads/accounting_details`) and schema-v1 receipt reader | Existing scripts, tests and already-created receipts name Slurm helpers or predate `scheduler_component` | Resolve only an installed, enabled `slurm` scheduler; never a checkout path. Retire after old-job validation and a declared receipt boundary |
| `results/slurm/<execution>` receipt directory | Existing receipts, publication manifests and synced results use this path for every scheduler | Historical storage name only; renaming requires a versioned receipt layout and reader (phase 5) |
| Saved Optuna import targets (`src.app.tuners.optuna.*`, `src.plugins.components.bundled.optuna.*`, `src.app.pipeline.tuners_optuna/optuna_utils/optuna_sweeper`) | Saved Hydra targets, sweeper discovery and checkpoints | `import_aliases` loads them from the installed, enabled Optuna component of the process workspace, with canonical identity; absent → actionable `ModuleNotFoundError` |
| `provider_object(package, 'file.py:attr')` | Installed packages written before declared exports | Loads undeclared helpers without requester validation; new code uses `provider_export`. Retire after bundled/installed callers migrate |
| Root launchers and `plot` forwarding modules | Existing CLI commands and saved plotting targets | Keep forwarding identity through consolidation; installed entry points become canonical |
| Pre-portable site receipt reader in `src/app/pipeline/tuner_execution_compat.py` | Existing schema-v1 receipts reserved Optuna paths without provider declarations | Metadata-only compatibility for receipts without `tuner_execution`; retire only after old-job validation and a declared receipt retirement |
| `PluginContext.window` and direct `frontend.plugins.base`/`frontend.plugins.context` imports | Third-party app plugins written before SDK 1.0 | Unsupported; bundled plugins use the SDK and context services only. Retire at SDK 2 |
| Direct `src.app.core.model_registry` and `src.app.objectives` imports in installed Hub packages and authored `src/usr` packages | Written before SDK 1.1 exported model registration and objective results | Same objects as the SDK exports. Installed packages switch when they are republished for the phase 4 cutover; authored packages before phase 7 enforcement covers every package |

Package format/API versions and workspace layout versions are separate contracts. The `in/` cutover is hard: after it, released storage-v2 archives that target `in/config` are rejected and their components are republished in the new format, and historical result records keep their old paths for viewing only (see the plan's [confirmed decisions](../plans/LAYER_BOUNDARY_IMPLEMENTATION_PLAN.md#confirmed-decisions)). Source relocation must preserve canonical objects for checkpoints; remote bundles need versioned manifests and readers for existing jobs. Migration must inventory ignored files, detect conflicts, acquire locks, preserve modes/bytes, write a complete timestamped backup before moving anything, and be safe to rerun after interruption; restore from that backup is manual. No automatic conflict winner, symlink shortcut, archive rewrite or destructive research-workspace migration is allowed.

## Reproducible inventory

Run `python -m src.app.workspace_inventory --workspace PATH --output FILE`. The read-only inventory includes ignored local source/inputs, file hashes/modes, tracked status, symlinks, package metadata, config selectors, intended destinations, ownership state and structured dataset references. Keep populated-workspace inventories private: paths may identify research inputs. Run the same command against a clean external workspace for the separate distribution baseline. Inventory is evidence, not permission to migrate files.
